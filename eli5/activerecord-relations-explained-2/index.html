How Rails loads books

A relation keeps a request for records and can hold the records it loads.

What this playground models
  • The page uses an in-memory teaching model; it runs no Rails code or SQL.
  • Each category change builds a fresh, unloaded request, sorted by title.
  • It leaves out adapters, the SQL query cache, console inspection, async loading, and associations.
  • Other calls, such as count, can query the database without loading these Book objects.

2. Chain another rule

Adding order(:title) returns a new relation with the sort rule while keeping the original request unchanged.

Original relation

fiction = Book.where(category: "fiction")

Rule: fiction

order(:title)→

New relation

books = fiction.order(:title)

Rules: fiction + title order

Both requests are unloaded in this example.

Why chaining works
  • These query methods return relations, so you can add more query rules.
  • The new relation starts unloaded even when the original relation is loaded.

Other ways to load
  • books.each { |book| ... } also loads this relation before reading each record.
  • books.load loads the records and returns the relation itself.
  • to_a returns a copy of the records array; the Book objects are shared.

4. Read them again

When stored records get stale
  • Later database changes do not refresh these records automatically.
  • books.reload clears the stored records and fetches them again.
  • A fresh relation has its own loading state.
