The Meat Proxy Problem

Published August 19, 2026. Revised August 29, 2026.

TL;DR

Forwarding an AI's answer unread, with nothing else checking the claim, severs accountability. Telling people to "just validate it" will not fix that. Review culture already rubber-stamps real code. The fix has to survive the same incentives.

The August 19, 2026 version is at meat-proxy-problem-20260819.

Niklas Gruhn coined the term "meat proxy" for a specific failure mode: pasting unread AI output into Slack, pull requests, or email and acting as an unthinking conduit. Someone trusts you sent something you stand behind.

Gruhn's remedy is simple: read it, understand it, validate it, and state it in your own words. But "review it more carefully" was the standard advice for human-written code too. That review culture was already failing before LLMs arrived.

Why it happens

The polish is part of the problem. A February 2026 breakdown of Anthropic's product data found that finished-looking AI output makes people less likely to double-check it. I haven't seen Anthropic's numbers directly, only how the thread characterized them. Users caught fewer missing-context problems and questioned the reasoning less when an answer already looked done. A rough draft invites a second look; a polished one invites a click.

A fix you can check

Will Larson calls it establishing the author as the first human in the loop. Whoever generates a document with AI must verify it before anyone downstream sees it. Skipping that step turns the recipient into the first real reviewer. At scale, that creates a poisoned reasoning layer where teams spend months solving problems that don't exist because the initial analysis was never checked.

Cindy Sridharan sets a stricter bar for code: understand close to 100% of the production code an LLM generates. Weak understanding produces vague prompts, vague prompts produce worse code, and worse code becomes harder to understand next time.

Where the rule bends

Peter Steinberger ships production code he never reads, leaning on tests and observability. A company run by Yaçine MTB stopped doing code review entirely, arguing that AI agents already catch mistakes at generation time.

The two cases are not equal. Steinberger's tests and dashboards operate independently of the model that wrote the code. Yaçine's agents checking AI output do not. Comprehension can be delegated only when an independent verification channel (a test suite, a compiler, runtime metrics) exists. A paraphrased answer in a Slack thread or a summary in a PR comment has no such channel.

Some model output is checkable: code that executes, math that resolves, citations that exist. Other output resists verification: open-ended rhetoric, persuasive synthesis, ungrounded commentary. Validate the first kind before forwarding. For the second, do not forward it.

The part exhortation can't fix

Larson's rule and Sridharan's rule remain moral appeals rather than structural incentives. Code review already demonstrated that appeals do not survive deadlines. A developer on r/ExperiencedDevs described a pull request that sat unreviewed for two days, then received approval within a minute of a direct message ping. A 2025 Journal of Systems and Software study surveyed developers at a mid-sized company; most reported that reviewers avoid or superficially skim large patches. I read the abstract through search rather than the paywalled full text, so treat that as reported rather than confirmed.

If "did CI pass, click approve" was already the default for human-written code, "read the AI's answer carefully" is the same unused instruction. Gruhn named the failure, but exhortation fails because no system provides an incentive for the reviewer to look.

A related essay examines whether a contribution removes uncertainty for the next person or transfers it. This essay focuses on the immediate threshold: when an AI answer sits in front of you, a coworker is waiting, and you decide whether to read it.

What I hold myself to

I do not have a documented production outage from an unread PR. This analysis is inferred from developer behavior rather than an incident report.

My operational rule labels all agent output unverified until independent tooling confirms it. Polish is not proof. Forwarding unverified text signs your name to an uninspected guess.

This is still personal discipline rather than a systemic fix that alters organizational incentives. The razor test is simple: would you defend this claim in your own voice if it turned out to be wrong? If the answer is no, you were acting as the pipe.
